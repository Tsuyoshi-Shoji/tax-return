## テーブル定義書

本テーブル定義書は、ユーザーアカウントを管理する `m_user` テーブルの構造を定義する。

`m_user` は、ログイン情報およびユーザーの基本情報を管理する親テーブルであり、収益・支出などユーザー単位で保護すべき業務データから参照される。

## テーブル名

### m_user

| No | 論理名       | 物理名                | 型            | PK | NN | UQ | デフォルト                                         | 説明                                                |
|----|-----------|--------------------|--------------|----|----|----|-----------------------------------------------|---------------------------------------------------|
| 1  | ユーザーID    | user_id            | BIGINT       | ○  | ○  | ○  | AUTO_INCREMENT                                | ユーザーの一意識別子。                                       |
| 2  | ユーザー名     | username           | VARCHAR(100) |    |    |    | NULL                                          | 画面表示用のユーザー名。未入力を許容する。                             |
| 3  | メールアドレス   | email              | VARCHAR(255) |    | ○  | ○  |                                               | ログインIDとして使用するメールアドレス。                             |
| 4  | パスワードハッシュ | password_hash      | VARCHAR(255) |    | ○  |    |                                               | BCrypt などの安全な一方向ハッシュで保存したパスワード。平文・復号可能な暗号文は保存しない。 |
| 5  | ステータス     | status             | VARCHAR(20)  |    | ○  |    | ACTIVE                                        | アカウント状態。例: ACTIVE, LOCKED, DISABLED。              |
| 6  | 最終ログイン日時  | last_login_at      | DATETIME     |    |    |    | NULL                                          | 最終ログイン日時。                                         |
| 7  | ログイン失敗回数  | failed_login_count | INT          |    | ○  |    | 0                                             | 連続ログイン失敗回数。                                       |
| 8  | ロック解除予定日時 | locked_until       | DATETIME     |    |    |    | NULL                                          | 一時ロック中の場合の解除予定日時。                                 |
| 9  | 登録日時      | created_at         | DATETIME     |    | ○  |    | CURRENT_TIMESTAMP                             | レコード作成日時。                                         |
| 10 | 更新日時      | updated_at         | DATETIME     |    | ○  |    | CURRENT_TIMESTAMP ON UPDATE CURRENT_TIMESTAMP | レコード更新日時。                                         |
| 11 | バージョン     | version            | BIGINT       |    | ○  |    | 0                                             | 楽観ロック用バージョン。JPA の `@Version` に対応する。               |

## 制約

| 種別          | 対象      | 制約名             | 内容                |
|-------------|---------|-----------------|-------------------|
| PRIMARY KEY | user_id | pk_m_user       | ユーザーIDを主キーとする。    |
| UNIQUE      | email   | uq_m_user_email | メールアドレスの重複を許可しない。 |

## 推奨インデックス

| インデックス名           | 対象カラム  | 用途        |
|-------------------|--------|-----------|
| idx_m_user_status | status | 有効ユーザー検索。 |

## 備考

- 新規登録時、`email` とパスワード入力値は必須とする。
- パスワード入力値はアプリケーション側で安全な一方向ハッシュ化を行い、DB には `password_hash` のみを保存する。
- `password_hash` に UNIQUE 制約は付与しない。同じパスワードを利用したユーザーの存在を DB 制約から推測できる設計を避ける。
- ログイン認証失敗時は、メールアドレスの存在有無やパスワード不一致の詳細を画面に出し分けない。
- 収益・支出など会計データを取得・更新する際は、必ずログインユーザーの `user_id` と紐づくデータのみを対象とする。
