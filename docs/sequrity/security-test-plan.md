# セキュリティ検証計画

> 対象: 収支管理および確定申告アプリ。版: 0.1。作成日: 2026-10-08。
> 状態: 個人利用向け暫定設定。責任者・承認者・最終レビュー日: 本人 / 本人 / 2026-10-08。
> 実構成、対策の実装、試験結果は個人利用向けに整理済み。候補・計画を実施済みと扱わない。

## 個人利用の前提

単独利用を前提とし、実施者・レビュー者・承認者は本人に統一する。外部委託、常設当番、複数承認者は置かない。検証対象は本人の端末、ローカルDB、ローカルアプリ、合成データを基本にする。

## 対象・実施条件

既存6指示とrisk-register.mdに対応する検証計画であり、テスト結果ではない。実装・採用機能に合わせて手順を詳細化する。未採用機能は根拠付きで対象外にし、未実施を合格としない。

- 対象URL、環境、所有者、実施者、許可された範囲・時間・負荷・手法を事前登録する。第三者サービスを無許可で攻撃しない。
- 原則検証環境と合成データを用いる。提供者APIはモック・sandboxを優先し、本番での実施は独立した承認と制限を必要とする。
- 管理者、一般A/B、別テナント、無効・退職相当、権限不足のアカウントを用意する。秘密・本番個人情報を証拠へ貼らない。
- RTO/RPO、セッション期限、入力上限等の期待設定を実施前に承認する。未設定の場合は判定不能と記録する。
- 予期しない漏えい・可用性低下・制御不能な負荷を観測したら停止し、incident-response.mdへ移行する。

## 頻度と実施方法

| タイミング | 必要な検証 |
| --- | --- |
| PR・ビルド | 関連ユニット・統合試験、秘密検査、依存・静的検査 |
| 公開前・重大変更 | 関連ケース、動的検査、認可・漏えい・会計整合性の確認 |
| 認証・データ・AI変更 | T-001〜T-007,T-010〜T-012,T-016〜T-018の影響範囲 |
| 年1回以上 | 独立性を確保した侵入テスト範囲の検討、復旧・事故訓練、管理レビュー |
| 事故・新脆弱性・提供者変更 | 該当ケースの再実施と回帰検証 |

自動検査だけで合格とせず、認可・業務ロジック・契約・運用は手動レビューを組み合わせる。負荷・侵入検査の範囲は事前に明確化する。

## リリース判定

認可回避、他テナント漏えい、秘密露出、確認前AI操作、帳簿改ざん・不整合、復旧不能などの重大問題を未解決のまま合格扱いにしない。その他の未解決事項もリスク所有者が代替対策・期限付きで判断し、法令・契約違反は受容しない。未実施・判定不能の必須ケースは検証完了として扱わず、公開判断へ明示する。

実施結果をrisk-register.mdの残余評価、control-mapping.mdの証拠・検証状態へ反映する。文書作成をもって試験済みとしない。
