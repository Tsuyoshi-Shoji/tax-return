## 1. 画面概要

選択した年度（会計年度）の帳簿データをもとに、青色申告の申告書類作成に必要な情報（基本情報・年間収支・損益計算書・決算整理・貸借対照表・仕訳帳）を確認・編集し、PDFとして出力する画面。

- **JSP ファイル**: `TaxReturn/tax-return.jsp`
- **URL パス**: `/tax-return`
- **HTTP メソッド**: GET（表示・年度切替）、POST（決算整理保存・申告方式変更）
- **パンくず**: ホーム ＞ 確定申告
- **認証**: 必須（未ログインはログイン画面へ遷移）
- **前提・注意**: 本画面の計算値は申告準備のための参考値であり、e-Tax等への自動提出は行わない。税務判断は利用者の責任で確定する。

## 2. 業務仕様

### 2.1 目的

| 項目 | 内容 |
|------|------|
| 目的 | 個人事業主が日々登録した収益・支出（複式簿記の仕訳）を集計し、青色申告決算書（損益計算書・貸借対照表）の作成に必要な数値を確認・補完して出力する |
| 利用者 | ログイン済みの個人事業主（自分の帳簿のみ参照・編集可能） |
| 利用時期 | 年末の決算整理〜翌年の確定申告期間 |

### 2.2 業務ルール

| No | ルール |
|----|--------|
| B-01 | 対象は「申告対象」として登録された収益・支出のみ。申告対象外データは集計に含めない |
| B-02 | 会計年度は 1/1〜12/31（個人事業主）。年度は `fiscal_year` の `period_start`〜`period_end` で判定する |
| B-03 | 年間売上 ＝ 当年度の収益（売上高＋雑収入）の合計 |
| B-04 | 年間経費 ＝ 当年度の経費科目（売上原価・減価償却費含む）の合計 |
| B-05 | 所得（当期純利益） ＝ 年間売上 − 年間経費 |
| B-06 | 青色申告特別控除後所得 ＝ 所得 − 青色申告特別控除額。控除額は所得を超えず、結果の下限は0 |
| B-07 | 青色申告特別控除額は利用者が10万円・55万円・65万円から選択する。選択は適用可否の判定ではなく、法定要件は対象年分の公式資料に基づき利用者が確認する |
| B-08 | 売上原価 ＝ 期首棚卸高 ＋ 当期仕入高 − 期末棚卸高 |
| B-09 | 貸借対照表は「資産合計 ＝ 負債・資本合計」が成立していること（貸借一致）。不一致の場合は警告表示し、PDF出力時にエラーチェックで検知する |
| B-10 | 貸借対照表の資本の部の「青色申告特別控除前所得」は当期の所得（B-05）と一致させる |
| B-11 | 決算整理項目（期首/期末棚卸、減価償却費、売掛金、買掛金、未払金、未収入金、期首残高、期末現預金）は利用者が入力する。保存後に損益計算書・貸借対照表へ反映する |
| B-12 | 仕訳は借方合計 ＝ 貸方合計。未確認の仕訳が残る場合、決算チェックで警告する |
| B-13 | 確定（締め）済み年度は決算整理の編集を不可とする。訂正は訂正履歴を残して再オープンまたは取消仕訳で行う（証跡のない上書きは禁止）。現行実装は「締めの取消（理由必須）→訂正→再締め（訂正理由必須）」で行い、取消仕訳による訂正は未実装（§4.7.3） |
| B-14 | 金額は円単位の整数（`BigDecimal`、スケール0）。丸めは端数切捨て |
| B-15 | 前年比は前年度（`taxYear - 1`）の同一指標との差額・増減率。前年データが無い場合は「-」を表示 |
| B-16 | マイナンバー・本人確認書類は本画面で取得・表示・出力しない |

### 2.3 申告方式と青色申告特別控除

| 申告区分 | 控除額 | 利用者に示す主な要件 |
|----------|--------|----------------------|
| 青色申告特別控除 10万円 | 最高100,000円 | 55万円・65万円控除の要件に該当しない青色申告者向け。簡易な記帳が認められる場合がある |
| 青色申告特別控除 55万円 | 最高550,000円 | 正規の簿記（一般に複式簿記）による記帳、貸借対照表・損益計算書等の確定申告書への添付、期限内提出 |
| 青色申告特別控除 65万円 | 最高650,000円 | 55万円控除の要件に加え、期限内のe-Tax送信、または優良な電子帳簿の備付け・保存と必要な届出等のいずれか |

控除額・要件は年分により改正され得るため、対象年分の国税庁公式資料を確認する。控除選択は利用者の申告予定区分であり、選択したことだけで適用要件を満たしたと判定しない。利用者が青色申告承認および選択区分の要件を確認した旨を年度単位で保存する。これは利用者の申告であり、証明とは扱わない。

アプリが機械的に確認する範囲は、生成した仕訳の借貸一致、帳簿から集計した貸借対照表の一致、未確認仕訳等のアプリ内整合性に限る。複式簿記としての法的適格性、青色申告承認、提出期限、e-Tax送信完了、優良な電子帳簿の法定要件・届出は判定・保証しない。65万円控除の方法（e-Tax／優良な電子帳簿／未確認）を選択できるが、e-Taxは本アプリから送信せず、優良な電子帳簿ルートは本アプリでは未対応であることを表示する。

#### 2.3.1 申告方式・控除区分別の必要書類と出力前検出

`FilingRequirements` が保存済みの申告方式（`business_profile.filing_type`）・控除区分・65万円の追加要件方法・利用者確認と、帳簿データ（仕訳有無・借貸一致・未確認仕訳・損益データ・貸借一致・決算整理保存・固定資産有無）、`BlueReturnEdition` の確認済み申告期限、当日（JST）から、書類・条件ごとに「要否（必須／該当時必須／任意／対象外）」と「状態（充足／不足／利用者確認／対象外）」を判定する。結果は控除区分セクションの `table-filing-requirements` に表示し、エラー・警告に加えるため、既存の出力抑止（エラー：PDF・ZIP・CSVをサーバーで拒否）と出力前確認（警告：画面で確認ダイアログを表示し、PDF・ZIPはサーバーでも `confirmed=true` を要求）が適用される。

| 書類・条件 | 10万円 | 55万円 | 65万円 | 不足・利用者確認の検出 |
|---|---|---|---|---|
| 青色申告承認・控除要件の利用者確認 | 必須 | 必須 | 必須 | 未確認は利用者確認（警告） |
| 取引の基本記録 | 必須 | 必須 | 必須 | 取引・仕訳なしは利用者確認（警告） |
| 簡易帳簿（現金出納帳・売掛帳・買掛帳・経費帳） | 必須 | 任意 | 任意 | 10万円で取引なしは利用者確認 |
| 仕訳帳・総勘定元帳 | 任意 | 必須 | 必須 | 仕訳なし・借貸不一致は不足、未確認仕訳は利用者確認 |
| 固定資産台帳・減価償却 | 該当時必須 | 該当時必須 | 該当時必須 | 登録資産がなければ対象外 |
| 青色申告決算書（損益計算書） | 必須 | 必須 | 必須 | 損益データなしは不足（警告） |
| 貸借対照表 | 任意 | 必須 | 必須 | 貸借不一致は不足、決算整理（期末残高）未保存は利用者確認（警告） |
| 申告書・決算書の期限内提出 | 対象外 | 必須 | 必須 | 期限未確定・期限前は利用者確認、確認済み期限の翌日以降は不足（10万円が上限となる旨の警告） |
| 65万円の追加要件 | 対象外 | 対象外 | 必須 | 未確認・優良な電子帳簿（未対応）は不足、e-Taxは利用者確認（いずれも警告） |

申告方式が青色申告でない場合はエラーとし、帳票を出力しない。判定は出力物・データの有無とアプリ内整合性に基づく案内であり、控除の適用可否や法定要件の充足を判定・保証しない。DB変更はない。

#### 固定資産台帳の独立CSV（2026-11-12）

`TaxReturnService.exportFixedAssetLedger` は認証利用者が所有する年分を解決し、その事業者の登録資産・イベントだけを取得する。期間を指定しない場合は選択年末以前に取得（私用転用は転用）した資産を取得日・ID順にすべて出力し、決算画面では省略される償却済み・過年度売却／除却済み資産、未供用資産も含める。期間指定時は期間末までに認識され期間開始前に処分されていない資産を抽出し、イベント行は期間内に限る。科目指定時は資産科目で絞り込む。償却額・残高は選択年分全体の値である。選択年末後の認識資産・イベントは含めない。通常取得の翌年以降の供用開始日は予定日として保持し、当年償却は0円とする。登録資産がない場合はヘッダーだけを出力する（指定時は抽出条件行を含む）。

| 行区分 | 項目 |
|---|---|
| 資産（1資産1行） | 年分、資産ID・名、科目コード・名、取得日、供用開始日、取得価額、取得資金区分、償却方法コード、耐用年数、償却率、当年償却月数、期首未償却残高、当年償却費、当年事業専用割合、当年必要経費算入額、償却累計額、売却・除却時未償却残高、期末未償却残高、状態（未供用／保有／売却済み／除却済み）、資産備考 |
| イベント（1登録1行） | 年分、資産ID・名、イベントID、区分（SALE／DISPOSAL／BUSINESS_RATIO_CHANGE）、適用日、変更後事業専用割合、売却価額、イベント備考。各資産行の後に適用日・ID順に出力 |

償却は帳票・仕訳と同じ `DepreciationCalculator` を使い、事業専用割合は年度開始時点までの最新変更を採用する。当年取得・転用資産の期首残高は0円。通常資産は当年償却後の簿価を処分時簿価とし、処分後の期末残高を0円にする。一括資産は処分後も3年間の残高・償却を保持する。過年度通常処分資産は当年の期首・償却・必要経費・期末を0円とし、処分年までの累計・処分時簿価・履歴を残す。「事業供用後償却累計額」は事業開始簿価（取得価額−私用減価）から償却後簿価を控除した額で、私用期間の減価や処分による簿価減少を混ぜない。

取得資金・償却方法は保存コード（7方式）を出力する。CSVは42列。従来29列の後へ耐用年数根拠、法定年数、取得時経過月数、中古確認、転用区分、私用減価、事業開始簿価、計算段階、改定取得価額、保証額、250％経過措置確認、ルール版、償却基礎金額の13列を追加する。イベント行は追加列を空欄とする。帳簿一括CSV・転記CSV・画面・印刷にも償却基礎金額や計算根拠を出力する。旧定額の基礎額は取得価額×90％（無形は100％）、定率は期首残高又は固定した改定取得価額、旧5年均等は残5％−1円。削除済み履歴、過去版の再現、法的適格性、電子保存適合を保証しない。

他の帳簿出力と同様に、整合性エラー時はサーバーでも出力を抑止し、画面へエラーを通知する。警告時は画面で確認する。未認証は401、所有していない年分は404。CSVは既存帳簿と共通の文字列数式無害化・引用符エスケープ・CRLF処理を使用し、レスポンスにはno-store・nosniffを設定する。DB変更は不要。

`AccountMappingHarness` で取得・供用・償却・期末の既存帳票との一致、当年売却・除却、過年度売却、償却済み・未供用・資産なし、割合変更履歴、年末後データの除外、CSV列数・数式対策、他利用者／所有しない年分の拒否、不整合時の出力抑止を確認する。

## 4. 処理詳細

### 4.1 画面表示処理（`GET /tax-return`）

1. セッションから認証済みユーザーIDを取得する（リクエストのuser_idは信頼しない）。
2. `year` パラメータを検証。未指定の場合はユーザーが持つ最新の `fiscal_year` を採用。
3. `fiscal_year` を「ユーザーID＋taxYear」で取得（他ユーザーの年度は取得不可）。
4. 以下を取得・集計し `TaxReturnPageData` を組み立てる。
   1. 基本情報（ユーザー・`business_profile`）
   2. 年間収支サマリー（今年度・前年度）
   3. 月別収支（12か月）
   4. 損益計算書の科目別集計
   5. 決算整理項目（保存済み値。未保存は0）
   6. 貸借対照表（期首・期末）
   7. 仕訳帳（先頭5件）
   8. 決算チェック結果
5. `TaxReturn/tax-return.jsp` へフォワードして描画する（出力時はHTMLエスケープ）。

### 4.2 集計・計算処理

| 処理 | 計算式・内容 |
|------|-------------|
| 年間売上 | `Σ income_entry.amount`（申告対象・当年度・本人分） |
| 年間経費 | `Σ expense_entry.amount`（申告対象・当年度・本人分）＋減価償却費（決算整理） |
| 売上原価 | 期首棚卸高＋当期仕入高−期末棚卸高（B-08） |
| 所得 | 年間売上−年間経費（B-05） |
| 青色申告特別控除後所得 | `max(0, 所得 − 控除額)`（B-06） |
| 前年比（額） | 当年値 − 前年値 |
| 前年比（率） | 前年値が0の場合は「-」。それ以外は `(当年−前年)/前年×100` を小数第1位で四捨五入 |
| 月別損益 | 月別収益−月別支出 |
| 貸借対照表（期末） | 現金・預金は期末現預金、売掛金・買掛金・未払金・未収入金・棚卸資産は決算整理値、元入金は期首残高、事業主貸借は事業主勘定の集計から取得 |
| 青色申告特別控除前所得 | B-05の所得をそのまま設定（B-10） |
| 貸借一致判定 | 資産合計（期首・期末それぞれ）＝負債・資本合計 |

計算は金額を `BigDecimal` で行い、浮動小数点を使用しない。税額・合計の算出は決定的な業務ロジックで行い、AIの回答には依存しない。

### 4.3 決算整理保存処理（`POST /tax-return/settlement`）

1. 認証・CSRFトークン検証。
2. `year` から本人の `fiscal_year` を取得（所有者条件付き）。存在しない／確定済なら拒否。
3. 各項目をサーバーで検証（3.3参照）。
4. トランザクション開始。
5. 決算整理テーブルへ upsert（`fiscal_year_id` 単位）。更新者・更新日時・版（楽観ロック）を記録。他で更新されている場合は競合エラーとして再読込を促す。
6. 変更内容を監査ログに記録（利用者ID・年度・項目名・日時・結果。金額本文は最小限）。
7. コミット後、`GET /tax-return?year=..` へリダイレクト（PRG）して再描画。二重送信は冪等に扱う。

### 4.4 エラーチェック処理

| No | チェック | 重大度 | 内容 |

| 1 | 基本情報の必須項目 | エラー | 氏名・住所・申告方式の未設定 |
| 2 | 貸借一致 | エラー | 期首・期末の資産合計≠負債・資本合計 |
| 3 | 仕訳の借貸一致 | エラー | 取引ごとに借方合計≠貸方合計 |
| 4 | 月別合計と年間合計の一致 | エラー | 月次合計≠年間合計 |
| 5 | 青色申告特別控除前所得の一致 | エラー | 貸借対照表の値≠当期純利益 |
| 6 | 決算整理の未入力 | 警告 | 減価償却費等が未保存 |

エラーが1件以上ある場合はPDF出力を拒否し、警告のみの場合は確認ダイアログの上で出力を許可する。

### 4.5 PDF出力処理（`GET /tax-return/pdf/{type}`）

1. 認証・認可（認証済み利用者が所有する年度のみ）を検証。`type` は許可リスト（`return` / `balance-sheet` / `profit-loss` / `journal` / `ledger` / `final-return` / `consumption`）。確定申告書と消費税計算書は対象データがある場合のみ出力できる。
2. エラーチェック（4.4）を実行。重大エラーの場合は出力を拒否。
3. 画面と同一の `TaxReturnService.load` によるデータを使い、画面の印刷グループに対応するセクションだけをPDF化する。外部URLや画面CSSを取得せず、JSPのエスケープ済み文言・表データをサーバーで構成する。
4. OpenPDFの日本語CIDフォントで帳票・表を生成する。対象年度、生成日時（JST）、計算ルール版を記載する。計算ルール版は `TaxReturnPdfRenderer.CALCULATION_RULE_VERSION` で管理し、計算ロジック変更時に更新する。
5. `Content-Disposition: attachment`、`Cache-Control: no-store`、`X-Content-Type-Options: nosniff` を付与する。ファイル名は許可済み種別と年度からサーバーで生成する。
6. PDF・ZIPはメモリー上だけで生成し、サーバー側に一時ファイルを残さない。
7. アプリケーション全体で同時PDF生成を2件までに制限し、仕訳帳・元帳は各10,000明細、ZIPは50 MiBを上限とする。上限超過時は生成せず、個別PDFまたは帳簿CSVの利用を案内する。
8. 出力操作の監査ログには利用者ID・年度・種別・結果のみを記録し、帳票本文・金額・氏名・住所を記録しない。

### 4.5.1 PDF一括ダウンロード（`GET /tax-return/export/pdfs.zip`）

選択年分で利用可能な個別PDFを同じサーバー生成処理で作成し、固定名のPDFファイルをZIPに格納する。エラーがあれば全体を拒否し、警告がある場合は画面で確認したリクエスト（`confirmed=true`）のみ許可する。ZIP生成中にエラーが発生した場合は部分アーカイブを返さない。データベース変更は不要。

### 4.6 申告区分・控除要件確認処理（`POST /tax-return/filing-type`）

1. 認証・CSRF・確定済年度チェック。
2. 控除値（10 / 55 / 65）と65万円控除方法（`UNCONFIRMED` / `ETAX` / `QUALIFIED_EBOOKS`）を許可リストで検証する。65万円以外では方法を `NONE` に正規化する。
3. 控除区分と利用者の要件確認状態、追加要件方法を `settlement_adjustment` に年度単位で保存する。未確認でも選択は保存できるが、チェック・警告で確認を促す。
4. 更新後に再表示し、青色申告特別控除後所得を再計算する。
5. 利用者確認は自己申告として扱う。アプリ内の借貸一致・貸借一致等と別に表示し、法定要件の充足を示すステータスにしない。

### 4.7 年分別保存管理台帳（`POST /tax-return/retention`）

1. 認証済みユーザーの所有する `fiscal_year` を年分で解決する。リクエスト由来の所有者IDは使用しない。
2. `TRANSACTION` / `EVIDENCE` は同じ年度の仕訳を関連付け、`BOOK` は年度全体の記録として個別仕訳を持たない。
3. 書類種別・名称・保存期限ルールを必須とし、文字数・形式・日付を検証して `retention_record` に保存する。保存期限は4.7.2のルールでサーバーが計算する。ルール対象外の年分や手入力を選んだ場合は、保存起算日・期限・根拠を利用者入力とする。
4. 年度画面に保存台帳と期限案内を表示する。登録レコードは実効期限（登録期限と最低保存期限の遅い方）まで、および保全中は削除・上書きしない。誤記訂正・変更履歴の仕組みが整うまでは利用者が保存根拠を再確認する。
5. 電子帳簿保存法等の電子保存の適合表示は実装せず、未判定である旨を明示する。

#### 4.7.1 証憑ファイルの保管（Google Drive）

設定・送信データ・運用は [GOOGLE-DRIVE-SETUP.md](../../../GOOGLE-DRIVE-SETUP.md) を参照。サーバー設定（OAuthクライアント、暗号鍵）が揃わない場合は機能を無効と表示する。

**停止中（2026-11-13〜）**: 将来提供予定の機能として `EVIDENCE_UPLOAD_ENABLED=true` を設定するまで停止する（既定 `false`、`GoogleDriveSettings.isEnabled`）。停止中は画面に今後提供予定の旨のみ表示し、連携パネル・アップロード・Drive確認・ファイルのダウンロードリンクを出さない。サーバーは連携開始・コールバック完了・アップロード・ダウンロード・確認を拒否し（所有者確認は従来どおり先に行う）、証憑ファイルのある台帳記録の削除も拒否する。連携解除（トークン失効）と、台帳の登録・検索・期限管理・保全・ファイルのない記録の削除は利用できる。コード・テーブル（V14）は保持する（`EvidenceFileHarness` で停止時の拒否を確認）。

1. **連携**: 利用者ごとに OAuth 2.0 認可コード＋PKCE（S256）で `drive.file` スコープのみを要求する。state・code_verifier・利用者ID・期限（10分）はセッションに保持し、コールバックで一度だけ取り出して利用者一致・期限・state（定数時間比較）を検証する。付与スコープに `drive.file` がない場合は許可を失効して拒否する。更新トークンはAES-256-GCMで暗号化して `evidence_drive_connection` に保存し、アクセストークンは保存しない。初回に Drive へ「確定申告アプリ 証憑」フォルダーを作成する。
2. **アップロード**: 所有者条件で台帳記録を解決し、3.3の検証後、サーバー生成名 `evidence-{id}-{UUID}.{拡張子}` で Drive に保存する。元ファイル名は表示用に無害化してDBのみに保存する。保存後のサイズ不一致・DB登録失敗時は Drive のファイルを削除する（補償処理）。SHA-256・サイズ・MIMEを `evidence_file` に記録する。
3. **ダウンロード**: 10 MB上限で取得し、SHA-256が登録値と一致しない場合は `MISMATCH` として返却しない。`Content-Disposition: attachment`、`X-Content-Type-Options: nosniff`、`Content-Security-Policy: default-src 'none'; sandbox`、`Cache-Control: no-store` を付与し、ファイル名はサーバーで生成する。
4. **確認**: Drive 上の存在・ゴミ箱・サイズを確認して検証状態（`OK` / `MISSING` / `TRASHED` / `MISMATCH`）を更新し、一覧の「要確認」に表示する。
5. **検索**: キーワード（書類種別・名称・根拠・関連仕訳・ファイル名）、記録区分、状態で、本人の年分内の台帳を絞り込む。件数・期限経過件数・要確認件数を表示する。
6. **削除期限管理**: 実効期限（4.7.2）の翌日以降かつ保全中でない場合のみ削除を許可し（期限当日まで拒否）、Drive のファイルを完全削除してから `evidence_file` と `retention_record` を削除する。Drive 削除に失敗した場合は台帳を残す。
7. **連携解除・失効**: 解除時は Google へトークン失効を要求して接続行を削除する。Drive 上のファイルは残る。Google 側で許可が取り消された場合（`invalid_grant`・401）は接続行を削除し、再連携を求める。
8. **監査**: `audit.evidence` に操作・利用者ID・台帳ID・結果のみ記録し、トークン・ファイル名・内容を記録しない。

制限事項: マルウェア検査は未実装（期限付き例外として [GOOGLE-DRIVE-SETUP.md](../../../GOOGLE-DRIVE-SETUP.md) に記録）。Drive 上での利用者による削除・差替えは防止できず、確認・ハッシュ照合で検知する。誤アップロードは保存期限まで削除できない。

#### 4.7.2 保存期限ルール・期限案内・保全（2026-11-12）

根拠: 所得税法施行規則63条（青色申告者）・102条（白色申告者等）、消費税法施行令50条1項、国税庁タックスアンサーNo.2070・No.2080（e-Gov 法令検索・国税庁サイトで確認日 2026-11-12）。`RetentionRules`（ルール版 `R2026-11-12`）で決定的に計算する。

| ルール区分 | 対象 | 青色 | 白色等 | 起算日 |
| --- | --- | --- | --- | --- |
| BOOK_MAIN | 主要帳簿（仕訳帳・総勘定元帳） | 7年 | 7年（法定帳簿） | 年分の翌年3月16日 |
| BOOK_OTHER | 補助簿その他の帳簿 | 7年 | 5年（任意帳簿） | 年分の翌年3月16日 |
| SETTLEMENT_DOC | 棚卸表・貸借対照表・損益計算書等 | 7年 | 5年 | 作成日の属する年の翌年3月16日 |
| CASH_DOC | 領収書・預金通帳等の現金預金取引等関係書類 | 7年 | 5年 | 作成・受領日の属する年の翌年3月16日 |
| OTHER_DOC | 請求書・納品書・見積書・注文書・契約書等 | 5年 | 5年 | 作成・受領日の属する年の翌年3月16日 |

1. 申告方式は `business_profile.filing_type` から取得し、リクエスト値を使わない。期限は起算日からN年後の前日。
2. 「消費税の仕入税額控除に使用」を選ぶと、翌年3月1日（課税期間末日の翌日から2月を経過した日）から7年も計算し、遅い方を採用する。
3. 前々年分所得300万円以下の5年特例、消費税の5年特例など期限を短くする特例は自動適用しない（早期削除の防止を優先）。
4. 対象年分の最低保存期限（翌年3月16日から5年）を下限とする。手入力ではこれより前の期限を拒否し、V15以前の記録も削除判定時に下限を適用する。
5. 根拠文には条項・期間・確認日・ルール版を自動記録する。2024〜2026年分以外はルールを選択できず、手入力で公式資料に基づき登録する。
6. 期限案内: 各記録に実効期限、残日数、期限間近（90日以内）・期限経過（削除可能）・保全中（削除不可）・手入力（ルール未適用、再確認を促す）を表示し、件数を集計する。
7. 保全: 税務調査・更正の請求・紛争等のため、所有者が理由（200字以内）を付けて保全・解除する。保全中は期限経過後も削除を拒否する。`audit.retention` に操作・利用者ID・記録ID・結果のみ記録し、理由は記録しない。

制限事項: 計算結果は法令適合・税務判断を保証しない。書類区分の選択は利用者が行う。電子帳簿保存法の要件、国税通則法の更正期間・訴訟保全の要否は判定せず、保全の要否は利用者が判断する。年分の改正は確認日以降のものを反映していない。

#### 4.7.3 年度締め・訂正履歴・出力帳票の生成記録（2026-11-12）

1. 締め（`POST /tax-return/close`）: 年度を所有者条件付きで行ロックし、未締めであること、前年以前の年度がすべて締め済みであること（翌年期首残高の前提）、画面のエラーがないこと、警告がある場合は `warningsConfirmed=true` を検証する。過去に締めた年度の再締めでは訂正理由（200字以内）を必須とする。成功時は `fiscal_year.status='closed'`・`closed_at` を設定し、`fiscal_year_closing_event` に CLOSE（締め版番号＝既存最大＋1）を追加する。
2. 締め時の記録項目: 売上・経費・所得・控除後所得・控除区分・期末資産・期末負債・仕訳行数・借方／貸方合計、会計データ指紋（年分・控除区分・売上等・決算書欄・貸借対照表行・全仕訳行の正規化文字列の SHA-256。氏名・住所等の基本情報は含めない）、計算ルール版（`TaxReturnPdfRenderer.CALCULATION_RULE_VERSION`）、様式参照版（`BlueReturnEdition.code`）。
3. 締めの取消（`POST /tax-return/reopen`）: 理由必須。翌年以降に締め済み年度がある場合は拒否する。取消時点の集計値と指紋を REOPEN（取消対象の締め版番号）として追加し、その締め版で出力した記録を SUPERSEDED（旧版）にして年度を open に戻す。
4. 訂正履歴: CLOSE／REOPEN を時系列で表示し、再締めでは前回の締め版との差分（売上・経費・所得・控除後所得・期末資産・仕訳行数・控除区分、金額同一で明細のみ変更の場合はその旨）を表示する。履歴は更新・削除しない。
5. 確定済み年度の改変検知: 締め済み年度の表示・出力時に現データの指紋を最新の CLOSE と比較し、不一致ならエラーとして全出力を止める（締め記録のない既存の締め済み年度は警告）。
6. 出力記録: PDF（個別・ZIP一括）、e-Tax転記補助CSV、帳簿CSV、固定資産台帳CSVのダウンロードごとに `report_output_record` へ帳票種別・ファイル名・ファイルの SHA-256・サイズ・データ指紋・計算ルール版・様式参照版・年度状態・締め版・生成日時を記録する。PDFフッターには記録と同じ生成日時・計算ルール版・様式参照版・年度状態（締め版）・指紋（先頭12桁）を印字する。画面では直近30件と、旧版・取消・現データとの不一致を表示する。誤配布等の出力記録は理由を付けて取消（CANCELLED）にできる。
7. 監査ログ: `audit.year-closing` に操作・利用者ID・年分・締め版・結果のみを記録し、理由は記録しない。

制限事項: 取消仕訳（反対仕訳）による締め済み年度の訂正は未実装。出力ファイル本体は保存しない（ハッシュ照合のみ）。様式参照版は本アプリの識別子で国税庁の公式な版番号ではない。締めは本アプリ内の変更制御であり、電子帳簿保存法の訂正削除履歴要件への適合や改ざん防止を保証しない（DB管理者による履歴自体の改変は検知対象外）。所得控除等の一部入力の保存処理は年度の行ロックを取らないため、締めとの同時実行で締め直後に変更が入る可能性が残る（その場合は指紋不一致として検知される）。

指紋の版（2026-11-12.2）: 会計データ指紋（第2版）は決算書欄を欄コードと金額（0円の欄を除く。任意記載欄は科目名を含む）で正規化し、様式の欄番号・欄名に依存しない。欄番号整合（4.7.4）より前に締めた年度の指紋（第1版）は `YearSnapshot.legacyFingerprint` で再現して一致と扱うため、整合だけで締め済み年度が「変化あり」にならない。第1版の締めと第2版の再締めを比較した訂正差分で合計額が同じ場合は「仕訳・帳票明細の内容変更、または指紋の算出方式の更新」と表示する。

### 実装メモ（2026-10-11）

- 当時のPDF出力はブラウザの印刷ダイアログ（「PDFに保存」）で実現。2026-11-12の実装メモでサーバー生成方式へ更新。
- エラーチェックは画面表示時にサーバーで算出し、ダイアログに表示（`POST /tax-return/check` は不要）。
- 住所・電話番号・業種は現行データモデルに項目がないため「未設定」表示。必須チェックの対象は氏名のみ。
- 青色申告特別控除（65/55/10）は `settlement_adjustment.blue_deduction` に年度単位で保存（既定65）。
- 控除要件の利用者確認と65万円控除方法は `blue_deduction_requirements_confirmed` / `blue_deduction_65_method` に年度単位で保存。アプリの整合性検査と法定適用要件の確認は区別し、後者を自動判定しない。
- 減価償却費と棚卸調整（期首棚卸−期末棚卸）は原則12月の経費として月別収支・損益計算書へ加算。通常資産の当年処分までの償却費は処分月へ加算する。
- 貸借対照表の元入金は「期首残高＋期首棚卸」、期末の青色申告特別控除前所得は当期の所得。
- 仕訳帳・総勘定元帳は収益・支出明細から借方／貸方を導出して表示（受取・支払方法未設定時は普通預金／現金）。
- 未確認の仕訳は `accounting_transaction.status = 'draft'` の件数。
- 内訳リンクは損益一覧（`/profit-loss`）へ遷移。

### 実装メモ（2026-11-01：勘定科目マスタと様式欄対応）

- 勘定科目マスタ `ledger_account`、決算書様式欄 `statement_line`、科目→欄対応 `account_statement_mapping`、品目→科目対応 `ui_item_account_mapping` を追加（Flyway `V5`）。初期値は `AccountMasterSeed` で起動時（`AccountMasterInitializer`）に未登録分のみ投入し、登録済みの行は上書きしない。
- 収益・支出の登録時、仕訳の科目は品目→科目対応から決定し、`journal_line.account_code` に科目コードを記録する。「その他」区分の支出（借入金元本返済等）はマスタのB/S科目、通常の経費を申告対象外にした場合は事業主貸で仕訳する。
- 起動時、未確定年度の仕訳明細で科目コード未設定の行に科目コードを補完する。旧実装で品目名を科目名として記録した借方行は、対応する勘定科目名へ読み替える。
- 損益計算書は勘定科目別に集計する（品目名では表示しない）。決算書の欄番号は令和6年分の様式構成を基に初期設定しており、年度ごとに国税庁様式での確認が必要。

### 実装メモ（2026-11-01：貸借対照表・固定資産・源泉徴収・所得控除・税額・消費税・出力）

#### 貸借対照表（仕訳残高から作成）
- `BalanceSheetService` が当年分の全仕訳（取引・決算整理・減価償却・固定資産取得）の残高から作成する。
- 前年分の帳簿がある場合、資産・負債の期首残高は前年の期末残高を繰り越し、元入金＝期首資産合計−期首負債合計。事業主貸・事業主借・控除前所得は期首に0へ戻す。
- 最初の年分は決算整理の「期首残高」（普通預金）・「期首棚卸」と、期首より前に取得した固定資産の未償却残高を期首残高とする。
- 科目を特定できない仕訳は「未分類」として資産側に表示し警告する。仕訳から計算した所得と損益計算書の所得が一致しない場合はエラー。

#### 決算整理仕訳（`ClosingJournalService`）
- 取引の保存・削除、決算整理の保存、固定資産の登録・削除の都度、未確定年度（当年以降）の次の仕訳を再生成する。
  - 決算整理仕訳：棚卸調整に加え、決算整理を保存済み（`settlement_adjustment.balances_confirmed`）の場合は売掛金・未収入金・買掛金・未払金を入力した期末残高に合わせ、差額を普通預金との決済として計上。
  - 減価償却仕訳：減価償却費（必要経費分）＋事業主貸（家事分）／資産科目（直接法）。
  - 固定資産取得仕訳：私的資金で取得した資産は 資産／事業主借。支出登録の「固定資産購入」（工具器具備品）で記帳済みで科目が異なる資産は工具器具備品から振替。
- 起動時にも全事業者の未確定年度を再生成する（以前の手入力の減価償却仕訳を置き換える）。

#### 固定資産台帳（`section-fixed-assets`、`POST /tax-return/assets`、`/tax-return/assets/delete`）
- 2024〜2026年分の新定額・200％定率・250％定率・旧定額・旧定率・少額特例・一括償却に対応。`DepreciationRules` が取得日・科目の制限、対象年分、特例上限、利用者確認を検証する。計算耐用年数2〜50年、既存5資産科目が対象。建物本体等の科目、1952年以前取得、特殊償却・税額控除は対象外。
- 旧新の取得日境界は2007-04-01、250％／200％は2012-04-01。2012年4〜12月取得で250％を継続する経過措置は資産ごとの利用者確認を要求する。ソフトウェア及び2016-04-01以後取得の建物附属設備の定率法は拒否する。
- 法定償却率は耐用年数省令別表七〜十に基づく `DepreciationRates` の表を使用する。新定率は期首残高×率の円未満切上げ額が取得価額×保証率未満となった最初の年の期首残高を改定取得価額として固定し、以後は改定率を使用する。2年の新定率は率1、保証・改定なし。
- 旧有形の定額は取得価額×90％×旧率、旧定率は期首残高×旧率。未償却残高が取得価額5％（円未満切上げ）に達した翌年以後、2008年分を下限として残5％−1円を5年均等償却する。旧ソフトウェアは90％・95％制限を適用せず0円まで償却する。
- `lifeBasis=USED_SIMPLIFIED` の場合、フォームの `usefulLife` は法定耐用年数として `statutory_useful_life` に保存し、計算年数はサーバーで算出する。一部経過は法定月数−取得時経過月数×80％、全部経過は法定月数×20％を12で割り、最後に年未満切捨て・最低2年。有形のみ、経過月数0〜2400。取得後の私用期間は経過月数に含めない。合理的見積困難、取得・供用時の選択、資本的支出なし等の利用者確認を要求する（50％超は簡便法不可。本アプリは中古簡便法を使う親資産への資本的支出を未対応とする）。
- `privateUseConversion=true` は通常5方式の有形・OWNER_FUNDS・取得日より後の供用日・法定年数が必須。私用減価＝取得価額×90％×旧定額率（法定年数×1.5の年未満切捨て）×私用年数。私用期間は6か月以上切上げ・未満切捨て、円未満切上げ、取得価額95％（円未満切捨て）上限。私用減価には旧方式の5年均等を適用しない。転用日に減価控除後簿価を資産／事業主借として計上し、転用前の年分には資産・償却を計上しない。償却方式は元の取得日で判定し、転用後の定額の基礎額は元取得価額等、定率は減価控除後残高とする。
- `POST /tax-return/assets/events` と `/tax-return/assets/events/delete` で事業専用割合変更、売却、除却を登録する。割合変更は年度初日限定。売却・除却は実際の処分日とし、通常5方式は供用開始月から処分月を含め月割り（円未満切上げ）。同月取得・供用・処分でも1か月。確定年度に影響する登録・削除を拒否する。転用登録の影響年は取得日でなく転用日から判定する。
- 有形資産の備忘価額は1円、ソフトウェアは0円。通常資産の売却損益は事業主勘定へ分離し、事業所得の雑収入・雑費に含めない。譲渡所得等は未対応のため該当年の所得税額を表示しない。通常資産の除却損は当年償却後簿価の事業分だけを必要経費、家事分を事業主貸とする。
- 一括償却は供用年の取得価額合計を3分の1にして円未満切上げし、ID順で各資産へ端数配分する。初年・翌年を同額、3年目に端数残額を償却する。途中で売却・除却しても残額を即時経費にせず3年の償却を継続する。売却代金の事業分は雑収入、家事分は事業主借とする。業務上基本的に重要な資産等の例外、廃業・相続による残額処理は対象外。
- 少額特例は10万円以上、2026-03-31以前取得は30万円未満、2026-04-01以後取得は40万円未満。供用年の取得価額合計が年300万円（開廃業年は300万円÷12×事業月数）を超える登録は拒否し、既存超過データも出力エラーとする。少額特例は供用年を選択して登録する。税込／税抜、青色申告、中小事業者・従業員数等の対象者要件、取得／供用期限、貸付制限、他特例重複、明細添付等は年分の公式資料に基づく利用者確認とし、システムだけで適格と判定しない。
- `POST /tax-return/assets/rules` で年分別の範囲確認・償却方法適用根拠（法定／選定届出・みなし選定／変更承認／混在）・特例確認・事業月数1〜12・確認根拠500字・サーバー日時・ルール版（`年分-2026-11-12-v3`）を保存する。定率資産に法定方法だけの確認は不可。選定届出・変更承認等の適格性は利用者確認とし、証明書検証・届出は行わない。従来のv1／v2確認は拡張条件がない場合だけ維持し、相続・贈与・方法変更・資本的支出・廃業等がある年分はv3で再確認する。メモに個人情報・秘密情報を入力しない。選定届出の原則期限は事由の生じた年分の確定申告期限、変更承認申請は変更年3月15日（休日繰延あり）。
- 相続・贈与による取得は `POST /tax-return/assets` で資産と移転イベントを登録し、元の取得日・取得価額・償却方法を保ったうえで、承継日・確認済み簿価・根拠を記録する。既存資産の変更年1月1日付方法変更は `POST /tax-return/assets/events` で登録し、確認済み期首簿価と変更承認等の根拠を記録する。定額法・200％・250％定率法間を新簿価から計算し、250％から200％への移行も扱う。過年度実績の一致・税務上の適格性は利用者確認とし、相続・贈与と方法変更の併用、旧方式5年均等中の承継は対象外。
- `asset_origin=CAPITAL_IMPROVEMENT` は2007-04-01以後の資本的支出を親資産と同じ勘定科目・法定耐用年数の別資産として登録する。旧資産への取得価額加算、定率法の合算特例、旧資産に係る2007年以前の支出、中古簡便法の親資産は対象外。
- `BUSINESS_CESSATION` は通常償却資産について廃業日を含む月まで償却し、廃業時残存簿価を廃業年と後年の固定資産台帳に表示して私用転用・譲渡等の別処理を警告する。残額の自動消込・税額計算は行わない。一括償却資産の廃業処理は対象外。
- V13で資本的支出区分・親資産、イベントの引継ぎ簿価・変更後方法・履歴確認を追加する。V13移行は既存資産を通常取得とし、新しい履歴・確認を自動付与しない。ルール版は `年分-2026-11-12-v3` とする。旧v2確認は新しいイベント／資本的支出がない年分だけ維持する。
- V11は `tax_return_input` に確認項目を追加する。既存行は未確認、翌年への確認自動引継ぎはしない。資産・イベントの追加／削除後は影響する未確定年分のルール確認版・日時を消し再確認を要求する。範囲確認を外して保存すると確認を取り消す。未確認・対象外・上限超過時は帳簿一括・固定資産独立CSVを空にし、理由を表示する。登録・確認保存は事業者の行ロックで直列化し、上限判定と確認取消の競合を抑止する。
- V12は資産に耐用年数根拠・法定年数・中古取得時経過月数・中古確認・私用転用・250％継続確認を追加する。既存の取得価額・方式・計算年数を変えず、法定年数を既存2年以上の年数から補完し、特殊条件・利用者確認は自動付与しない。
- 仕訳・決算書・期首繰越・独立CSVは同じ処分日・一括償却プールを使う。通常資産の処分年の償却は処分仕訳に含め、その日に資産残高を消し込み、年末の償却仕訳には重複計上しない。独立CSVの処分時簿価は当該処分年の償却後残高を示す。一括資産は処分済みでも未償却残高を期末に残し、後年も償却する。
- 確定済み年度で償却している資産は削除できない。台帳の「支出登録済み」資産と支出登録「固定資産購入」の金額が一致しない場合は警告。
