## 画面概要
ユーザーの新規登録を行う画面。メールアドレスとパスワードの入力フォームを表示し、登録処理を行う。登録成功時はログイン画面へ遷移、失敗時はエラーメッセージを表示する。
既登録ユーザーへの導線としてログイン画面へのボタンも提供する。

- **JSP ファイル**: `Auth/user-register.jsp`
- **URL パス**: `/register`
- **HTTP メソッド**: GET（表示）/ POST（新規登録送信）
- **登録対象テーブル**: `app_user`（必須）、`user_setting`（同時作成）

### 画面レイアウト

- `screen-image/01_user-register/screen-01-user-register_image.png` を基に、淡色背景の中央に白い登録カードを配置する。通常は幅540pxを上限とし、高さに余裕があるPCでは最大668pxに広げる。
- 青いワードマーク、区切り線、4つの入力欄、規約同意、全幅の登録ボタン、ログインリンクを縦に並べる。狭い画面ではカード幅・余白を縮める。
- 上部にはPCで24px以上、モバイルで12〜16px以上の余白を確保し、カードが画面上端に接しないようにする。
- 表示領域の高さに応じて余白・文字・入力欄をコンパクト化し、通常の初期表示を1画面に収める。コンパクト表示では装飾の区切り線を省略する。エラー表示や文字拡大時は内容を隠さず自然な縦スクロールを許可する。
- パスワードと確認欄の目のアイコンは自作SVGを使用し、それぞれ独立して表示を切り替える。
- 規約同意は初期状態では未選択。利用規約・プライバシーポリシーのリンクは準備中の通知を表示し、法務文書の提供済みを意味しない。

## API仕様

### `GET /register`

- 目的: ユーザー新規登録画面の表示
- レスポンス: `200 OK`（JSPレンダリング）

### `POST /register`

- 目的: 新規ユーザー作成
- リクエスト（Form）

| 項目 | 型 | 必須 | 説明 |
|------|----|------|------|
| name | string | ○ | 氏名。`app_user.display_name` に保存 |
| email | string | ○ | メールアドレス |
| password | string | ○ | 平文パスワード（受信後に保持しない） |
| confirmPassword | string | ○ | 確認用パスワード |
| termsAgreement | boolean | ○ | 利用規約同意 |

- 正常時レスポンス
  - `302 Found` でログイン画面（`/login`）へリダイレクト
- 異常時レスポンス
  - 入力不正: `400 Bad Request`
  - メールアドレス重複: `409 Conflict`
  - システムエラー: `500 Internal Server Error`

## バックエンド検証仕様

- `email` の形式および必須チェックをサーバー側で再検証する。
- `password` は8〜72文字をサーバー側で再検証する。
- `password` と `confirmPassword` は一致必須とする。
- `termsAgreement=true` を必須とする。
- `app_user.email` の重複を検査し、重複時は登録を拒否する。
- パスワードはハッシュ化して `app_user.password_hash` に保存し、平文は保存しない。

---

## セッション管理仕様

- 新規登録完了時点では認証セッションを発行せず、ログイン画面へ遷移する。
- 途中入力値をセッションに保持する場合は最小化し、パスワードは保持しない。
- 登録POSTはCSRF対策を通過したリクエストのみ受け付ける。

---

## 監査・ログ

- 登録成功/失敗を監査ログへ記録する。
- 記録項目: 実行日時、結果（成功/失敗）、失敗理由カテゴリ、送信元情報。
- ログにパスワード、トークン、Cookie値を出力しない。
- ログ要件は `docs/sequrity/security-test-plan.md` の `T-016` を満たす前提で実装する。

## バリデーションチェック（フロント）仕様

### 新規登録フォーム

| 項目 | チェック内容 | エラーメッセージ |
|------|------------|----------------|
| 氏名 | 未入力 | 氏名を入力してください。 |
| 氏名 | 100文字超過 | 氏名は100文字以内で入力してください。 |
| メールアドレス | 未入力 | メールアドレスを入力してください。 |
| メールアドレス | 正規表現 `^[A-Za-z0-9._%+-]+@[A-Za-z0-9.-]+\.[A-Za-z]{2,}$` | メールアドレスは正しい形式で入力してください。 |
| パスワード | 未入力 | パスワードを入力してください。 |
| パスワード | 8〜72文字の範囲外 | パスワードは8〜72文字で入力してください。 |
| パスワード（確認） | 未入力 | 確認用パスワードを入力してください。 |
| パスワード（確認） | パスワード入力欄との不一致 | パスワードが異なります。確認してください。 |
| 利用規約同意 | 未チェック | 利用規約・プライバシーポリシーへの同意が必要です。 |

## バリデーションチェック（バックエンド）仕様

| 項目 | チェック内容 | エラー応答 |
|------|------------|----------|
| name | 未入力/100文字超過 | `400 Bad Request` |
| email | 未入力/形式不正 | `400 Bad Request` |
| email | 既存ユーザーと重複 | `409 Conflict` |
| password | 未入力/8〜72文字外 | `400 Bad Request` |
| confirmPassword | 未入力/不一致 | `400 Bad Request` |
| termsAgreement | `false` | `400 Bad Request` |

## DB関連注記

- 参照テーブル: `app_user`, `user_setting`
- `app_user.email` はUNIQUE制約のため重複登録不可。
- `app_user.password_hash` はハッシュのみ保存し、平文パスワードは保持しない。
- `app_user.status` は初期値 `active` で登録する。
- `user_setting` は `app_user_id` に1:1で紐付き、初期 `home_apportionment_rate=0.00` を作成する。

## 実装上の注意

- `docs/architecture/coding-guidelines.md` に従い、Controllerで業務ロジックを持たずServiceへ委譲する。
- 登録処理は `app_user` と `user_setting` を同一トランザクションで作成する。
- 画面入出力は Form / DTO を使用し、Entityを画面へ直接渡さない。
- ログ出力は `System.out.println` を使わず、SLF4Jを利用する。
